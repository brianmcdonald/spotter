# Kenya Spotter

A Svelte web app for spotting and logging Kenya's indigenous **fish**, **birds** and **animals**.

- Three sections (Fish, Birds, Animals) plus a **My Log** tab
- **Species data from iNaturalist and eBird, limited to Kenya**: every indigenous species with research-grade iNaturalist records in Kenya, plus birds on eBird's Kenya checklist and coastal fish recorded from Kenya in *Coastal Fishes of the Western Indian Ocean*
- Search by name, family or place. Filter by rarity, IUCN conservation status, family/group, endemic species and spotted/not spotted. Sort by name, most observed in Kenya, rarity or threat level
- Each species has a swipeable photo gallery (tap to view full screen and zoom), descriptions grouped by source (Wikipedia and, locally, three field guides), its IUCN status, its number of Kenyan records and links to its iNaturalist and eBird pages. About 75 well-known species also have hand-written notes: size, diet, habitat, where to see it and a fun fact
- **Mark as spotted**: log the date, location and notes. Multiple sightings per species can be edited or deleted
- **Pick the location on a map**: tap to drop a pin, drag it to adjust, search for a place by name, or use your GPS location. The place name is filled in automatically unless you've typed your own
- **Export / import** the log as JSON (merge or replace), plus CSV export for spreadsheets
- Works offline for the species list and your log. Photos for hand-written species are bundled; other photos, descriptions, the map and place search need a connection
- Mobile-first, with iOS safe areas, a bottom tab bar and dark mode

## Getting started

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # static site in dist/
npm run preview    # serve the production build
npm run check      # type-check
```

### Species data (iNaturalist + eBird)

```bash
npm run species                        # iNaturalist only
EBIRD_API_KEY=your-key npm run species # also enrich birds from eBird
# …or save it once in a git-ignored .env file: echo "EBIRD_API_KEY=your-key" >> .env
```

`scripts/fetch-species.ts` uses only Kenyan data. It writes `src/lib/data/species.json` (bundled into the app), plus `public/data/summaries.json` (Wikipedia summaries) and `public/data/photos.json` (up to five more openly licensed photos per species for the gallery), both loaded when a species is opened. Re-run it now and then to pick up new records.

- **iNaturalist** (no key needed): species with research-grade observations in Kenya (place 7042), excluding species listed as introduced there. Sections: birds; ray-finned fishes and sharks/rays; mammals, reptiles and amphibians. Rarity is a species' rank by number of Kenyan observations within its section: top 20% Common, next 30% Uncommon, next 30% Rare, bottom 20% Very Rare. IUCN status uses a Kenya-specific assessment if one exists, otherwise the global Red List. Photos are limited to openly licensed ones and credited in the app.
- **eBird** (needs a free key from https://ebird.org/api/keygen): adds Kenyan checklist birds that iNaturalist lacks and uses eBird family names. Bird rarity is based on the share of Kenya's 60 richest hotspots that have recorded the species (50% or more Common, 20% Uncommon, 5% Rare, otherwise Very Rare). "Where to see it" lists those hotspots.

Observation counts reflect where people go and what they photograph, so rarity is a guide rather than a measure of population. That's why hand-written entries keep their own rarity: sanctuary rhinos would otherwise come out as "Common".

### Field guides

```bash
brew install poppler && pip3 install Pillow numpy   # once
npm run books                  # all books (~10 min the first time)
npm run books -- --only wiof   # just one: boea (birds), safari (animals) or wiof (fish)
npm run species                # then, to add the Kenyan fish the fish guide found
```

Put the PDFs anywhere under `sources/` (e.g. `sources/birds/`, `sources/animals/`, `sources/fish/`): *Birds of East Africa* (Stevenson & Fanshawe), *Jonathan Scott's Safari Guide to East African Animals*, and the five text volumes and four colour-plate volumes of *Coastal Fishes of the Western Indian Ocean* (Heemstra et al., NRF-SAIAB 2022; files named `*wiof_volume_*.pdf`). `scripts/extract-books.py` links their accounts to catalogue species by scientific name, common name or iNaturalist synonym, and writes:

- `public/books/books.json` and `public/books/img/`: each bird's identification, status and habitat (with country codes spelled out), voice and alternative names, a crop of its plate and the full plate; each Safari Guide chapter's key facts and sections (habitat, habits, food, reproduction, predation…), with its photos and captions; and each fish's description, distribution and remarks, with up to four colour-plate photos (with photographer credits) and a line drawing. The species page shows them under **Descriptions**, one block per source, and adds the pictures to the gallery.
- `src/lib/data/book-facts.json`: each bird's length and Kenyan abundance, and each fish's maximum size, used for size and rarity (hand-written values still win). These are facts rather than the books' text, so this file is committed.
- `src/lib/data/book-species.json`: coastal fish whose distribution in the fish guide names Kenya but which have no research-grade iNaturalist records in Kenya. `npm run species` adds them to the catalogue (marked as known from the book), with iNaturalist photos, summaries and IUCN status where iNaturalist has them. Their rarity comes from the guide's remarks ("common", "rare"…), or Rare if it doesn't say.

The books are copyrighted and their content is published here with the publishers' permission. The extracted text and pictures in `public/books/` are committed and deployed; the PDFs themselves (`sources/`, `*.pdf`) are git-ignored and never committed. The app skips the book content if `public/books/` is missing. The Safari Guide PDF is an OCR scan, so expect the odd misread word.

### Adding hand-written details

1. Add an entry to `src/lib/data/fish.ts`, `birds.ts` or `animals.ts`. It is matched to the generated data by scientific name and keeps its own `id`. Its text fields and rarity take priority over the generated data, while IUCN status and record counts come from the data.
2. Set `wiki` to the English Wikipedia article title and run `npm run images` to bundle its photo for offline use (on macOS, images are compressed with `sips`).

Map tiles come from [OpenStreetMap](https://www.openstreetmap.org/copyright), and place search and naming use [Nominatim](https://operations.osmfoundation.org/policies/nominatim/). Both are free for light use. If the app gets heavy traffic, switch to a commercial tile and geocoding provider (in `MapPicker.svelte` and `geo.ts`).

Photos come from Wikimedia Commons under their individual Creative Commons licences. Each species' detail view shows the credit and a link to the source.

## Turning it into an iPhone app

The app is built to wrap with [Capacitor](https://capacitorjs.com/):

- Vite uses `base: './'` and the router uses URL hashes, so the build works from a native WebView with no server
- All assets are local, so the app works offline
- Persistence, file export and geolocation are each isolated in one place

```bash
npm i @capacitor/core @capacitor/ios && npm i -D @capacitor/cli
npx cap init "Kenya Spotter" com.example.kenyaspotter --web-dir dist
npm run build && npx cap add ios && npx cap open ios
```

Recommended native swaps:

| Concern     | Web (now)                         | iOS (Capacitor)                                      |
|-------------|-----------------------------------|------------------------------------------------------|
| Storage     | `localStorage` in `storage.ts`    | `@capacitor/preferences` (iOS can clear WebView storage) |
| Export      | `<a download>` in `export.ts`     | `@capacitor/filesystem` + `@capacitor/share`          |
| Location    | `navigator.geolocation`           | `@capacitor/geolocation`, and add `NSLocationWhenInUseUsageDescription` to Info.plist |
